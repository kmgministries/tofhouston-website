# Results Matter Transition House — initial release

Static frontend lives at `/results-matter/` on tofhouston.org. Supabase handles authentication, PostgreSQL authorization, and private document storage. No server secret belongs in this repository.

## Activation

1. Run `setup.sql` once in the correct Supabase project's SQL Editor.
2. Configure Auth Site URL and redirect allowlist as `https://tofhouston.org/results-matter/`.
3. Request an account from the portal and confirm email. All new profiles are inactive Residents, irrespective of user-provided metadata.
4. The project owner must activate the initial administrator in the SQL Editor using the query generated by `setup.html`. Never promote an arbitrary first registrant.
5. Activate additional users in Administration. Link resident accounts through the resident profile form.
6. Exercise two different residents and staff roles before entering private operational data.

## Security model

Table writes are revoked from browser roles. Mutations use explicitly granted RPCs with a fixed module allowlist, input validation, and database permission checks. RLS separately restricts direct SELECTs. Resident access is restricted to their own shared data even if an administrator accidentally grants module permissions for confidential areas. Residents cannot modify internal case notes, incidents, financial entries, access assignments, document visibility, or approval decisions.

Roles are read from administrator-managed profiles, never client metadata. All new accounts are inactive. Browser sessions remain in memory; closing/reloading the tab requires a new login. Database sessions enforce a 20-minute inactivity window; successful user activity touches the session, and signout ends it. Supabase performs password hashing and optional TOTP MFA. No credentials or private records are stored in localStorage. Authentication email links necessarily carry one-time recovery credentials; URL fragments are cleared after processing.

Documents: private bucket, 5 MB maximum, PDF/JPEG/PNG/WebP allowlist. Signed URLs expire after 60 seconds. These links are not placed in profile URLs or public source. Upload paths use generated UUIDs. The upload MIME check is not antivirus scanning. Failed metadata saves can leave inaccessible orphan objects; administrators can remove them through the Supabase dashboard. Use trusted documents only until content inspection is added.

Public applications cannot read submissions. Basic email/day and global/hour submission throttles reduce accidental duplication but do not replace robust CAPTCHA or edge/IP rate limiting. Add abuse protection before promoting the public form broadly. Supabase authentication rate limits and email deliverability settings should be reviewed by the project owner.

Audit logs record record identifiers/actions without copying personal content. Exports require a dedicated permission and are audited. CSV fields guard spreadsheet formula injection. Archive preserves records; database deletion of private records remains an administrator data-retention responsibility.

## Included workflows

Sign in, account request/activation, password recovery, TOTP enrollment/verification, staff/resident role navigation, searchable/paged module lists, form-based CRUD, application review and conversion, property/room/bed setup, transactional bed assignment/transfers/move-out, case/reentry records, goals/tasks, programs/enrollments/attendance, house logs, incidents, document upload/access/typed signatures, fees/credits/payments/numbered receipts, resident requests/messages, announcements/resources, discharge/follow-up/outcome records, CSV reports, print/PDF reports, administrative permission controls, immutable user-facing audit history.

Detailed metrics and charts are based on up to 1,000 records per module; resident total count is exact. Basic reporting is not yet a complete funder-report suite. Supplemental form fields are JSONB objects inside relational tables; core resident, user, housing, and program relationships are foreign keys.

## Explicit remaining work

This is an initial implementation, not the entire 30-section specification completed and production-certified. Recurrence/reminder fields are descriptive only. Automatic notifications, email/SMS dispatch, automatic discharge/follow-up scheduling, comprehensive assessment templates, enrollment calendar expansion, global cross-module search, configurable admin taxonomies, native XLSX exports, dedicated integration adapters, robust public-form abuse protection, content-scanning uploads, granular column-level staff privacy, managed backup/restore, and production security review remain. Typed document signatures are stored with user/time; no external legal e-signature service is implemented. Financial entries record offline payments; no payment processing occurs.

No resident or financial records are hardcoded into the public frontend. The administrator can use Add DEMO data to insert clearly marked fictional examples into the protected database. Documents and user accounts are not faked by this action. Additional samples can be marked DEMO through the record form.
# Workspace redesign

The portal includes a daily work dashboard, permission-filtered workspace search,
and resident workspaces for overview, goals and tasks, case management, programs,
documents, financial ledger, transition and aftercare, and chronological history.
Adding a record from a resident workspace preselects that resident.
Search is limited to the first 1,000 accessible records in each supported module.
The sign-in screen is separate from administrator database activation instructions.
Local smoke checks cover workspace rendering and role-filtered navigation; browser
geometry and live database authorization tests remain outstanding.
